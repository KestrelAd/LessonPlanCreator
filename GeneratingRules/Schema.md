# 智能体教案 JSON 生成规约与排版指令综合指南 (V4.0)

---

## 一、 基础数据结构与键名规约 (Base Structure & Naming)

### 1.1 嵌套逻辑 (Nesting)
* 允许根据教学逻辑进行对象的层级嵌套（Nested Objects），但最底层的叶子节点必须包含 `x01` 到 `x91` 的原子键名。后端的 Python 脚本会自动进行深度遍历提取。

## 二、 列表排版引擎 (List Formatting Engine)

当输出一个 JSON 数组（Array）时，可以通过设置**“索引 0 标记位”**来精确控制 Word 中的排版样式。

### 2.1 样式触发指令
* **数字递增 (Standard Numbering)**：在数组第一个元素填入 `"n."`。程序将自动输出带有回车的 `1. `, `2. `, `3. ` 列表。
* **实心圆点 (Bullet Points)**：在数组第一个元素填入 `"•"`。
* **短横线 (Hyphen)**：在数组第一个元素填入 `"-"`。
* **默认机制**：如果数组第一个元素不是上述指令符号（即直接输出了正文），系统将默认采用数字递增（`1. 2. 3.`）排版。

## 三、 混合文本排版 (Hybrid Text & List)

当需要在同一个键值中**同时包含说明段落和格式化列表**时，必须使用 `||` 分隔符，并将所有内容打包在一个**超级字符串**中。

### 3.1 语法结构与渲染
* **标准格式**：`"前置段落文字 || [\"列表标记\", \"项1\", \"项2\"] || 后置总结文字"`
* **渲染逻辑**：程序会按 `||` 切分片段，识别出 JSON 格式的部分并自动进行列表转换，非 JSON 的普通文本保持原样。解析器会在段落与列表之间自动添加双换行符（`\n\n`）以保证 Word 中的段落间距。

### 3.2 致命警告与真实范例 (CRITICAL)
* ⚠️ **JSON 强制转义**：混合模式下的列表，其内部（尤其是数组内部）的所有双引号必须使用反斜杠进行转义，写成 `\"`！
* ❌ **引发崩溃的错误示例**：`"x01": "文本" || ["a"]` 
* ✅ **真实成功范例 (参考 `x46`)**:
  `"x46": "<u><i>Focus questions</i></u> || [\"What is a built in software instrument?\", \"How to add loops?\", \"Do you need to have a musical background.\"]"`

## 四、 富文本与颜色嵌套标签 (Rich Text & Color Tags)

在输出的字符串中，允许使用类 HTML 的轻量级标签来控制 Word 中的文字样式。**支持无限层级与任意样式的交叉嵌套**。

### 4.1 基础样式标签
* **加粗 (Bold)**：使用 `<b>...</b>`
* **斜体 (Italic)**：使用 `<i>...</i>`
* **下划线 (Underline)**：使用 `<u>...</u>`

### 4.2 字体颜色标签
使用首字母简写控制高亮颜色（内部已映射至十六进制标准色）：
* `<r>...</r>`：**红色** (Red)
* `<g>...</g>`：**绿色** (Green)
* `<bl>...</bl>`：**蓝色** (Blue) —— *注意：为避开加粗 b，蓝色强制使用 bl*
* `<y>...</y>`：**黄色** (Yellow)
* `<o>...</o>`：**橙色** (Orange)
* `<p>...</p>`：**紫色** (Purple)

### 4.3 真实嵌套成功范例
* **范例 1 (混合基础样式)**：参考 `x46` 中的 `"<u><i>Focus questions</i></u>"`（同时具有下划线和斜体）。
* **范例 2 (结合颜色与样式)**：参考 `x55` 中的 `"<u><r>Exit ticket</r></u>\n\nEnsure all students..."`（同时具有下划线和红色字体，后续跟上两个换行符和正文）。
* **范例 3 (深度嵌套)**：`"请注意：<u><b><r>严禁倒置公式</r></b></u>"`（同时渲染下划线、加粗且字体为红色）。

## 五、 生成逻辑准则与安全边界 (Directives & Restrictions)

### 5.1 教学逻辑对位
* **精准连贯**：严格按照 `introduction` -> `body` -> `conclusion` 的逻辑流分配时间与教学内容，确保教案在教学法上的合理性。

### 5.2 安全输出与排版禁令
* **JSON 解析安全**：在输出带有 `"`、`\n` 等特殊字符时，务必符合原生 JSON 转义规范，确保输出的 JSON 可被标准的解析器成功 `JSON.parse`。
* **禁止无意义占位**：严禁输出诸如 "Sample Text", "To be filled", "待补充" 等敷衍内容。无内容即输出 `""`。
* **禁止排版僭越**：绝不要在文本字段内尝试敲入大量空格来模拟“左右分栏”或“表格对齐”。所有物理布局均由后端的 `Template.docx` 模具绝对锁定，LLM 仅需负责纯粹的语义与标签输出。
