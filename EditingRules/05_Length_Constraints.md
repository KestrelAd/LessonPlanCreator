# 05_Length_Constraints

# 字段内容长度、颗粒度与排版限制 (Length, Granularity & Formatting Constraints)

为确保生成的教案符合专业标准与排版规范，所有字段的生成必须严格遵守以下宏观篇幅与微观字段限制：

## 宏观篇幅控制 (Macro Length Control)
一份完整的单节课教案（LEP）总等效文本量应在 **3~5页** 左右。其中，教学主体环节（The lesson itself）的篇幅应当占据 **2~3页**。所有文本必须摒弃散文式/论文式写作，以结构化、易扫视的格式呈现。

---

## 微观字段限制 (Micro Constraints by Field Type)

### 1. 极短文本 (标签型字段)
**适用字段：** `learning_area`, `lesson_focus`, `time`, `year_level`, `assessment_type`
**长度限制：** 1~5 个词组。
**排版要求：** 严禁出现完整的句子（例如：只能填“50 分钟”，绝对不能填“本节课的预估总时长为50分钟”）。

### 2. 清单型短文本 (课前准备与教具资源)
**适用字段：** 课前准备相关字段（如 `Preparation and Resources`）
**长度限制：** 每一项资源的描述遵循“极短文本”限制（1~5个词组）。
**排版要求：** 严禁写成完整的陈述句或长段落。必须使用**列表排版 (List all)**，将所需的所有物理材料、技术设备等逐一列出，确保任课教师课前能够一目了然。

### 3. 中短文本 (目标与评估描述)
**适用字段：** `broad_outcomes`, `specific_learning_goals` (数组内单项), `assessment_what`, `assessment_how`, `prior_knowledge`
**长度限制：** 允许扩展至 100~150 字左右。
**排版要求：** 必须提供广泛且详尽的解释（Extensive explanation）。特别是在评估部分，必须详细阐述“学生将如何展示学习成果”以及“为什么学习该内容是重要的”，以符合最高评分标准的要求。

### 4. 提问型文本 (焦点问题)
**适用字段：** 各个环节的 `focus_questions`
**长度限制：** 严格提供 2~3 个具体的问题原话。每个问题不超过 30 个字。
**排版要求：** 必须以问号结尾的完整疑问句呈现。

### 5. 概念定义专项 (词汇与概念)
**适用场景：** 在教案文本中（如 Instructional Input 环节）需要为学生生成专业词汇或新概念的定义时。
**长度限制：** 极其严格地限制在**最多 2 句话以内** (Maximum 2 sentences)。
**排版要求：** 必须是“学生友好型定义 (User-friendly definition)”，确保精简，绝对禁止长篇大论。

### 6. 反思型文本 (课后反思)
**适用字段：** `Reflections`
**排版要求：** 无需生成冗长复杂的段落，必须直接使用**点列式 (Dot points)** 进行精简概括。

### 7. 长文本 (教学策略与活动细节)
**适用字段：** 各个环节的 `strategies` (导入、主体、总结), `adjustments`
**排版与内容组织核心约束：**

* **绝对禁止散文式写作 (Dot points, not essay-style)：** 所有主体活动内容必须彻底摒弃连贯的段落式长文，强制使用点列式或列表形式，使得需要强调的要点高度突出。
* **师生行为双线分离：** 严禁将教师的动作和学生的动作混杂在同一个语段中。必须利用换行与标记与格式区分，将长文本明确切分为**“教师行为（Teacher：...）”**与**“学生行为（Students：...）”**两个视觉上完全独立的意群区块。
* **指令下达颗粒度限制 (防认知超载)：** 当生成“教师对学生下达的活动说明或操作指令”时，必须将其结构拆分为微小步骤。**每个信息块/步骤集最多只能包含 3 条并列指令**；如果涉及对学生而言是全新的行为，则**单次只能给出 1 条指令**。

**技术实现与 JSON 渲染逻辑要求：**
为了在最终生成的 Word 文档中实现上述复杂的列表排版，在输出长文本 JSON 数据时，需严格遵循以下机制：

1.  **数组排版控制位：** 当输出 JSON 数组时，通过设置“索引 0 标记位”精确控制 Word 样式：
    * **数字递增**：首元素填入 `"n."`（自动转为 `1. `, `2. ` 列表）。
    * **实心圆点**：首元素填入 `"•"`。
    * **短横线**：首元素填入 `"-"`。
    * **默认机制**：若首元素无上述指令符号，系统默认采用数字递增排版。
2.  **超级字符串混合排版 (`||` 分隔符)：** 当需要在同一个键值中同时包含前置说明文字（如 `Teacher:`）和格式化步骤列表时，必须使用 `||` 分隔符打包：
    * **标准格式范例**：`"Teacher: 引入新概念 || [\"•\", \"指令1\", \"指令2\"] || Students: 分组讨论"`
    * **渲染逻辑**：解析器会按 `||` 切分，自动转换 JSON 列表，并在段落与列表间自动添加双换行符（`\n\n`）以保证意群视觉隔离。
3.  **字体颜色标签控制：** 使用首字母简写控制高亮颜色（内部已映射至十六进制标准色）：
    * `<r>...</r>`：**红色** (Red)
    * `<g>...</g>`：**绿色** (Green)
    * `<bl>...</bl>`：**蓝色** (Blue) —— *注意：为避开加粗 b，蓝色强制使用 bl*
    * `<y>...</y>`：**黄色** (Yellow)
    * `<o>...</o>`：**橙色** (Orange)
    * `<p>...</p>`：**紫色** (Purple)
4.  **文本样式真实嵌套成功范例：**
    * **范例 1 (混合基础样式)**：参考 `x46` 中的 `"<u><i>Focus questions</i></u>"`（同时具有下划线和斜体）。
    * **范例 2 (结合颜色与样式)**：参考 `x55` 中的 `"<u><r>Exit ticket</r></u>\n\nEnsure all students..."`（同时具有下划线和红色字体，后续跟上两个换行符和正文）。
    * **范例 3 (深度嵌套)**：`"请注意：<u><b><r>严禁倒置公式</r></b></u>"`（同时渲染下划线、加粗且字体为红色）。
